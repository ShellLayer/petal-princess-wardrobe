# 开发与发布

本项目是纯静态网页，运行时无需服务器计算、数据库或外部接口。`server.cjs` 仅用于本机开发。

## 文件

| 文件 | 用途 |
| --- | --- |
| `index.html`、四份 CSS | 界面和大小屏布局 |
| `game-data.js`、`ancient-data.js`、`beauty-data.js` | 款式、历史分类、SVG 图案、妆容和配色 |
| `fitting-data.js`、`character-renderer.js` | 统一坐标、叠层遮挡、材质换色与预览 / 照片共用绘制 |
| `app.js` | 选择、翻页、撤销、照片、本机相册和设置 |
| `asset-manifest.json`、`assets.js` | 当前图片清单与浏览器入口 |
| `assets/` | 原始 PNG、生产 WebP、缩略图和遮罩 |
| `scripts/baselines/` | 重建素材所需的旧版清单，不依赖本机历史备份 |
| `tests/` | Playwright 检查 |

## 构建

```sh
npm ci
npm run build
npm run build:site
```

`build` 在根目录生成 `花间小公主.html`，图片与程序全部嵌入其中；生成文件不提交到 Git，离线版通过 Releases 提供。

`build:site` 还生成 `dist/`：只复制当前程序和清单引用的 WebP，排除原始画稿、文档、测试、开发依赖和历史备份。全部路径为相对路径，可部署在 GitHub Pages 的项目子目录，也可将 `dist/` 交给其他静态网站托管服务。

## 从原画重建素材

正常改文字或交互不必运行下面的步骤。原画与工具版本相同时，可以按顺序重建：

```sh
npm run assets:base
npm run assets:scenes
npm run assets
npm run build:site
```

第一步处理角色定位与基础素材；第二步重新压缩独立高清场景；第三步生成材质颜色和原图手部的遮挡。底稿清单位于 `scripts/baselines/`，相关原画和旧版切片在 `assets/` 中保留。不要删除 `assets/v3/` 和 `assets/v4/` 后再重建。

## 检查

```sh
npx playwright install chromium
npm test
```

测试会启动本机服务。Windows 会优先使用已安装的 Chrome / Edge；Linux 使用 Playwright Chromium。离线检查需要先运行 `npm run build`。部分测试会更新 `docs/v4/` 的示例截图，提交前请检查改动。

## GitHub Pages

仓库为公开仓库。在 `Settings → Pages → Build and deployment → Source` 选择 **GitHub Actions**。本仓库已提供 `.github/workflows/pages.yml`：

1. 对 `main` 的提交运行构建和浏览器检查。
2. 检查通过后将 `dist/` 发布到 Pages。
3. PR 只检查，不发布。Actions 还保留 14 天的离线 HTML 构建产物。

默认入口是 [在线试玩](https://shelllayer.github.io/petal-princess-wardrobe/)。Fork 后需在自己仓库启用 Pages，并将 README 的在线 / 下载链接改为自己的地址；自动部署采用当前仓库的 Pages 地址，不依赖这里的固定展示链接。

GitHub 官方说明：[使用自定义工作流发布 Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 新版本离线包

修改 `package.json` 版本并同步锁文件，运行构建和检查。将生成的 HTML、LICENSE 与简短使用说明打包后，作为对应 GitHub Release 的附件上传。生产站点只提供游戏；项目管理和下载入口放在仓库说明中。
